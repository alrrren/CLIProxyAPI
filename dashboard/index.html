How these numbers are calculated

Quota meters show remaining share = 1 − reported utilization for each window. A window whose reset time has passed shows no value until a new reading arrives; it is not assumed full. Quota is checked every ten minutes. Readings older than eleven minutes, after a failed quota check, or without an observation time, are marked unverified and excluded from the weekly total. Weekly capacity left adds each enabled account's remaining 7-day share, so 1.0 equals one account's full week; it is not a percentage of the pool.

Cache hit rate = cache-read tokens ÷ total input tokens, weighted by tokens rather than averaged per request. Records saved before explicit cache fields were added are excluded from that percentage. Coverage shows how many records have precise accounting.

Response time includes the entire request, including streamed output. Time to first token is shown only when the proxy reports it. Processed tokens count repeated context, including cached reads; they are not unique words or a subscription quota meter. One chat message can generate multiple requests through tools and background work.

Collection health reports the last successful poll. Missing records from outages cannot be reconstructed, and another queue consumer can remove records before this collector sees them. No historical data before collection began is included.
